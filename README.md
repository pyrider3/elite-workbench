# 菁英工作台 · 独立服务器版

这是可在自己的服务器运行的完整网站。前端 React，后端 Node.js，数据保存在 SQLite，打卡照片保存在本地磁盘；访问网站无需 ChatGPT 账号。没有 Cloudflare D1、R2、Sites 或云端 agent 的运行依赖。

## 快速启动

需要 Node.js **22.13 或更新版本**。复制 `.env.example` 为 `.env`，填写自己的 `INITIAL_PASSWORD_SUPERADMIN` 和可选的豆包密钥。首次启动自动创建数据库、迁移结构并导入需求文档中的 40 个固定班次。

```sh
npm ci
npm run build
node --env-file=.env server.mjs
```

默认访问 `http://127.0.0.1:3000`。源码仓库不包含构建产物，启动前须执行 `npm run build`。

开发界面时运行 `npm run dev`。开发与生产使用同一个 Node.js 后端；**生产使用 npm start**。

## 网站入口

- `/`：今日工作台、完整排班、个人档案、志愿时长申请、管理员入口。
- `/qing`：复用原 youth-elite-platform 的小菁对话式报名；提交到当前服务器的报名库。
- `/biao`：原项目手动报名表。
- `/wenjuan`：独立问卷入口，不在首页显示。
- `/health`：部署时检查服务运行状态。

## 环境变量

| 变量 | 默认值 | 用途 |
|---|---|---|
| `HOST` | `127.0.0.1` | 监听地址。容器中使用 `0.0.0.0`；反向代理部署通常保持默认。 |
| `PORT` | `3000` | HTTP 端口。 |
| `DATA_DIR` | 项目内 `data/` | SQLite 数据库与照片的持久化目录。可设置绝对路径。 |
| `PUBLIC_URL` | 空 | 对外网址，例如 `https://bgs.example.com`。启用 HTTPS 反向代理后填写，用于正确判断同源请求和设置 Secure Cookie。 |

Linux 示例：

```sh
HOST=127.0.0.1 PORT=3000 PUBLIC_URL=https://bgs.example.com npm start
```

PowerShell 示例：

```powershell
$env:PUBLIC_URL='https://bgs.example.com'
$env:PORT='3000'
npm start
```

## 业务规则

- 姓名直接作为个人身份，无需注册或个人密码。
- 排班人员可提前30分钟打卡，超过第一班迟到阈值后禁止打卡；同一个姓名同一班次只保存一次。
- 默认上班后 15 分钟以内（含第 15 分钟）打卡正常，下班时自动计入整班志愿时长。关闭浏览器不影响结算，无需签退或申请审核。
- 超过迟到阈值后禁止打卡，未打卡标记未到岗；特殊情况请联系办公室示例成员7，由管理员核实更正。历史迟到记录仍保留。
- 值班管理员可修改固定班次的星期、人员、场地及上 / 下班时间，新增或删除班次；可单独调整某一天、设置停班和请假。
- 固定排班变更同步到未来未开始且未单独调整的班次；已开始的历史快照保留。历史时长更正通过单条记录处理，填写原因，操作记录保留。
- 迟到阈值可由管理员调整，应用于未来未开始班次。
- 个人档案显示值班记录、累计值班时长及志愿总时长。值班时长自动计入志愿总时长；其他活动申请经超级管理员批准后计入。
- 请假入口显示办公室示例成员7及微信号，由管理员登记请假。

## 管理员

首次创建数据库的超级管理员密码由 `INITIAL_PASSWORD_SUPERADMIN` 指定；其他角色可配置 `INITIAL_PASSWORD_VIEWER/OFFICE/MEDIA/PROJECT/PRACTICE`，未配置的角色使用随机初始密码，请由超级管理员在后台重新设置。用超级管理员登录后，在「设置与记录 → 管理员账号」设置值班管理员密码，也可以修改其他角色密码。

权限在后端执行：超级管理员拥有全部权限；值班管理员管理排班、打卡异常、阈值和宣讲会同步；一般管理员查看全部报名；部门管理员查看本部门第一或第二意向报名、标记联系状态以及查看本部门问卷。登录会话在数据库中保存，服务重启后仍可继续使用，12 小时后过期。

## 宣讲会自动同步

后端进程内置定时器，按 **北京时间每天 05:00、11:00** 同步包含今天的未来七天校内宣讲会，与服务器操作系统的时区无关。

- 启动时同步一次；检查周期 30 秒。
- 同步成功的时段保存在 SQLite，重启会读取状态并重新获取最新信息。
- 学校接口失败时保留最后一次成功内容；5 分钟后重试，连续失败逐步延长间隔，最长 30 分钟。
- 管理员仍可手动同步。
- 保持 Node.js 进程在线即可，无需另设 ChatGPT 自动化或系统 cron。部署 agent 应配置进程守护，关机或进程停止期间无法执行定时任务，重新启动会补同步。

数据来源：https://sxufe.bysjy.com.cn/module/careers?menu_id=13369 。只读取公开的校内宣讲会数据。

## 数据与升级

`data/workbench.sqlite` 为数据库；`data/photos/checkins/` 为照片及对应类型信息。数据库启用 WAL。**运行数据不包含在交付包中**，这是新数据库，不会自动导入旧项目或之前在线预览的数据。

升级时替换源码与 `dist/`，保留 `DATA_DIR`。备份最直接的方式是停止服务后复制整个数据目录，再启动服务；不要只复制正在运行的 `.sqlite` 文件而遗漏 WAL 或照片。部署、迁移或调整域名的细节由你指定的部署 agent 完成。

## 原项目来源

小菁报名页面及对应交互资源来自 https://github.com/pyrider3/youth-elite-platform 。工作台页面和独立服务器实现位于 `src/`、`server.mjs` 与 `lib/`。这是按需求复用的报名模块，旧平台数据库需要单独迁移。

### 指定日期套用星期排班

值班管理员在「管理 → 值班与异常」选择日期，在「指定日期排班」选择周几，检查时间和名单后确认套用。两个场地一起替换，仅影响这个日期，保存当时固定排班的快照并保留审计记录。未安排班次的星期可用于整日停班。允许覆盖已有排班，包括已经开始或有打卡的日期。原排班及其打卡、处理记录保存在操作记录中；相同场地、时间和姓名的记录自动沿用到新班次，避免重复计时。未匹配的旧记录留档，不进入新排班的当前统计；套用没有班次的星期会清空当天排班。普通部门管理员没有这项权限。

拍照打卡入口统一在「值班安排」。同一栏目显示当前姓名的值班记录，可切换姓名查看；「个人档案」先显示志愿时长申请，再显示值班记录。未来尚未发生的班次在排班栏目查看，不计入档案的历史次数。主页宣讲会为包含今天的未来七天。

### 自动匹配打卡与连续值班

请假联系卡片在「值班安排」，联系办公室示例成员7，微信 `example-office-wechat`。管理员登记请假。

打卡提交姓名和照片，由服务器按当天排班与实际提交时间自动匹配；可在班次开始前30分钟（含边界）至第一班开始后的迟到阈值以内打卡（不含班次结束时刻）。同一场地、同一人首尾相接的班次形成连续值班段，一次照片打卡覆盖全段，各班次结束后分别按成员标签结算：普通成员每班2小时，大一成员每班3小时，不增加提前到场时长。连续段按第一班的迟到阈值判定，超过阈值后全段禁止打卡，不能等到第二班重新打卡。请假、停班、有间隔或不同场地不合并；同一时刻存在多个场地的排班时要求管理员核对。已有单班打卡的连续段再次提交会沿用已保存的照片和时间补齐后续记录，整段已完成时拒绝重复打卡。

### 成员标签与志愿时长

值班管理员和超级管理员在「管理 → 成员标签」按姓名标记或取消「大一」，名单来自已有固定排班及班次，也可手动添加姓名。标签统一按姓名生效，自动结算的已完成班次及未来班次使用同一标签；人工更正时长不被覆盖。普通成员每班2小时，大一成员每班3小时。连续两班一次打卡后分别结算，普通成员共4小时、大一成员共6小时。请假、停班、缺岗、超时迟到仍不自动计时；手工志愿申请不受标签影响。标签修改留存操作记录。

### 首页学期周次

日期卡片显示北京时间的月日、星期和学期周次，以2026年10月5日（周一）为第5周起点，每逢周一自动加一周。2026年10月11日为第5周，10月12日为第6周。计算见lib/calendar.js；下一学期启用时需更新该学期基准。

## 单框志愿申请与排名

志愿时长页面输入一句话（支持多人、多行），识别后可校对姓名、活动、时长和说明，再整批提交待审核。识别不会直接增加时长。全员排名包括排班成员、成员标签和活动申请中的姓名；按值班有效时长＋已审核通过活动时长降序排列，零时长成员隐藏，同分并列，每30秒刷新，可搜索姓名。待审核和拒绝的活动不累计。

识别直接调用火山方舟豆包 Responses API，服务器环境变量 `ARK_API_KEY` 配置密钥，`ARK_MODEL` 默认 `doubao-seed-2-0-mini-260428`。部署通过权限 0600 的 `deployment/ark.env` 加载密钥，该文件已加入忽略列表，不放入前端或迁移包。关闭深度思考、不使用联网工具、仅发送当前输入，不上传数据库或照片；`store:false` 不保存模型对话上下文。所有申请均由 AI 识别，失败保留原文并提示重试，不降级本地规则。相同文本缓存10分钟、最多100条，同内容并发请求合并；建议句式：张三、李四在双选会中搬物资，各加3小时。每次最多50条，每人每条0.01至100小时。

首页就业服务基地（学活）的“今日开门”按北京时间星期自动切换，展开可拨打电话或复制微信；安排及联系方式位于 `lib/door-contacts.js`。周末姓名按联系方式中的“示例成员42”填写。志愿申请支持“三个小时”“两小时”“一个半小时”等中文时长；全部使用豆包 API 识别。

## 历史协会备份导入

`scripts/import-legacy.py` 使用 Python 3 标准库，先核对 ZIP 中原 SQLite 与 JSON 导出的一致性。默认只检查：

```sh
python3 scripts/import-legacy.py /path/to/backup.zip --data-dir data
```

停服务后添加 `--apply` 执行导入，再重新启动。导入保留当前记录、原审核状态与时长；固定原表名及编号防重复，不覆盖已经导入后的人工修改。迁移前数据库和照片备份位于 `data/backups/`，原协会 JSON 和报告位于 `data/imports/`。不导入大数据社和 AI 文件任务。附件凭证仅超级管理员可查看。历史问卷的完整字段可以在问卷结果“查看”中读取。姓名登记原始记录以 `name-submission` 类型保留，不产生时长，也不自动设置大一标签。

已按正确备份“网站全部信息_2026-10-11.zip”校正为404条志愿记录（396条通过、8条拒绝），通过总时长1579.5小时、涉及141人；335条协会报名、149份问卷、35条姓名登记，50张原附件均保存。6条附件索引对应已不存在的旧记录，只归档不新增时长。活动名为空的313条保留原备注，不补造活动。

最新备份校正使用 `--sync-source`：新增源记录，更新未被本网站人工编辑的源记录，移除最新快照已删除的旧导入记录（完整留审计和备份），不会删除本网站新建记录。若源变化与本地人工修改冲突，停止应用并列出冲突。支持根目录raw-json以及带外层目录的records-json备份。不要用较旧快照执行此选项。

```sh
python3 scripts/import-legacy.py /path/to/latest.zip --data-dir data --sync-source
# 确认检查结果、停服务后执行
python3 scripts/import-legacy.py /path/to/latest.zip --data-dir data --sync-source --apply
```

校正新增94条志愿记录和22条报名，更新7条已联系状态，移除旧快照多出的1条志愿记录。其余当前业务记录保持不变。

部署交接：`elite-workbench-server.zip` 是程序包，`elite-workbench-data.zip` 是本次合并后的数据包；后者包含 SQLite、照片、原协会 JSON 和导入报告，排除浏览器登录会话与迁移前备份。新服务器首次迁移时将数据包解压到程序目录，保留 `data/` 路径；不要覆盖其他已有服务器的数据库。

本学期值班记录从2026年10月11日起统计；12月26日起停止排班，最后值班日为12月25日。此后不生成缺岗记录，历史值班记录和志愿时长保留。

AI输出使用精简结构 `{ "r": [["姓名", 小时数, "活动及服务内容", "日期地点补充"]] }`，服务端还原为原有字段，界面及提交协议不变。每行严格校验4列及字段类型，兼容旧对象格式；不降低完整性校验。小样本对比输出量约减少三分之一，耗时受服务排队和网络波动影响，不能保证每次更快。
